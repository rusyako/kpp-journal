# kpp-journal — инструкции для Claude Code

## Hikvision / ISAPI интеграция

Обязательные правила при любой работе с терминалами Hikvision, турникетами и Remote Verification:

- Перед разработкой интеграции прочитать `docs/hikvision/README.md` (индекс, обозначения источников, выводы, план пилота).
- Опираться на базу знаний `docs/hikvision/`; сырой текст документации — `docs/hikvision/raw/` (страницы помечены `<!-- page: N -->`).
- Проверять каждый endpoint и поле по первоисточнику (файл + раздел + страница), а затем по `capabilities` конкретного устройства. Не придумывать отсутствующие поля.
- Имена файлов в `ISAPI/` не совпадают с содержимым — пользоваться таблицей кодов FRT/ACET/EC/FD/LOG в `docs/hikvision/README.md`.
- Разделять «описано в документации» (DOC) и «подтверждено на оборудовании» (HW); результаты проверок на устройстве записывать в `docs/hikvision/`.
- Технические решения фиксировать в репозитории («Журнал решений» в `docs/hikvision/README.md` или отдельный файл), а не только в разговоре.
- Никогда не изменять реальные устройства без явного разрешения пользователя в текущем запросе: никаких PUT/POST/DELETE конфигурации, пользователей, прав, `httpHosts`, `AcsCfg`, команд открытия/закрытия (`RemoteControl/door`), включения Remote Verification. Сетевые запросы к школьным терминалам (даже GET) — только после разрешения. На первом этапе тестируется только `employeeNo = "3818077855"`.
- Не коммитить `hikvision_users.json` и другие выгрузки с ФИО учеников; не сохранять фото/шаблоны лиц.
