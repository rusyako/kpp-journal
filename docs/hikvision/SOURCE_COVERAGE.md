## 2. Метод конвертации

* **Конвертер:** MarkItDown MCP (`markitdown_mcp`, MarkItDown 0.1.9), инструмент `convert_to_markdown(uri)`.
  Для части файлов инструмент вызывался через MCP напрямую (Log Types — весь документ; FRT §10.16 — стр. 125–137).
  Для массовой конвертации вызывалась **та же функция** `markitdown_mcp.__main__.convert_to_markdown` из того же интерпретатора (`py -m markitdown_mcp`),
  чтобы результат записывался на диск без пересказа через модель. Её код — `MarkItDown(enable_plugins=…).convert_uri(uri).markdown`.
* **URI:** `file:///C:/…` (копии с правильными расширениями во временном каталоге; оригиналы в `ISAPI/` не изменялись).
* **Разделение PDF:** Python (PyMuPDF) только разрезал PDF на одностраничные файлы; каждая страница конвертирована отдельным вызовом,
  затем страницы собраны во фрагменты по 25 страниц с маркерами `<!-- page: N -->`. Номер в маркере = физическая страница исходного PDF (1-based).
* **Excel:** конвертирован целиком (единственный лист `Sheet1` в каждом файле — проверено openpyxl).

## 4. Проверка полноты (не просто «конвертер отработал»)

Скрипт сравнения — результаты в `raw/verification.json`.

### PDF: доля уникальных слов (≥4 символа) исходной страницы, найденных в Markdown той же страницы
Слова водяного знака исключены.

| Документ | Страниц в PDF | Страниц в MD | Пропущено страниц | Среднее покрытие | Мин. | Страницы < 97 % |
|---|---|---|---|---|---|---|
| ACET | 31 | 31 | 0 | 98,7 % | 92,9 % | 16, 19, 22 |
| CRC | 10 | 10 | 0 | 98,9 % | 88,9 % | 1 |
| FRT | 565 | 565 | 0 | **99,96 %** | 95,8 % | 199, 524 |
| LOG | 27 | 27 | 0 | 99,4 % | 95,6 % | 1, 4, 24 |

Все «потери» на страницах < 97 % вручную объяснены **водяным знаком**: буквы `vasiliy.chuikin@hta.kz` / `HTA` вклеены в слова и ячейки таблиц
(примеры: `cBelarus`, `HRussia`, `Interlock ing Door NotH Closed`, `Gias Detection`). Содержимое есть, но искажено.

### Excel: каждая непустая ячейка ищется в Markdown дословно

| Документ | Строк (вкл. заголовок) | Ячеек | Не найдено дословно | Причина |
|---|---|---|---|---|
| EC | 2271 (1 пустая) | 11 280 | 5 | экранирование Markdown (`\_`, `\*`) и многострочные ячейки (`\n`) — данные на месте |
| FD | 1955 | 13 680 | 26 | экранирование `\_`; одна ячейка со строкой `"None"` отображена как `NaN` |

Особенности конвертации Excel (pandas): целые коды статусов стали `1.0`, `4.0`; пустые ячейки — `NaN` (73 в EC, 6 в FD).
В EC 18 строк имеют китайский Status String `操作错误` (= Invalid Operation), а Status Code хранится то строкой, то числом — так в исходнике.
