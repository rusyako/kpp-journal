# Журнал выхода учеников через КПП

Версия на React + Python + Telegram вместо Google Таблиц + Apps Script.
Покрывает требования ТЗ Ф-1…Ф-25; сценарии приёмки П-3…П-13 проверяются автотестами API.

| Кто | Где работает | Что делает |
|---|---|---|
| Охрана | `/kpp` на компьютере КПП (логин и пароль) | Ищет ученика при наборе, отмечает «Вышел», снимает ошибочную отметку |
| Эдвайзер | Telegram Mini App (кнопка у бота) или `/advisor` в браузере | Пишет время и причину для своих учеников, видит «🚪 ЧЧ:ММ» |
| Руководство | `/report`, `/kpp` (только просмотр), отчёт в Telegram в 16:50 | Смотрит отчёт и журнал действий |
| Администратор | `/admin` | Список учеников, пользователи и приглашения, календарь, отчёты, проверка системы |

Что изменилось по сравнению с версией на Google Таблицах:
- лист дня — это выборка по дате, а не копия листа: нет 400 листов в год, ночной архивации и триггера 06:00;
- поиск идёт на лету при наборе, без Enter и без автозаполнения браузера;
- разрешение доходит до охраны меньше чем за секунду (WebSocket), без сверки раз в 5 минут;
- эдвайзер может менять только свои группы;
- если на КПП пропала связь, отметки сохраняются с временем нажатия и уходят на сервер позже (с пометкой 📴);
- нерабочие дни, каникулы и праздники задаются в календаре админки.

## Установка на сервер

Нужен Linux-сервер с Docker и домен, который указывает на этот сервер. Персональные данные детей лучше хранить на сервере в Казахстане.

1. Скопировать репозиторий на сервер. В `deploy/` выполнить `cp .env.example .env` и заполнить `.env`: домен, пароли, токен бота.
2. Создать бота у @BotFather, указать в `.env` `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`.
3. Запустить: `cd deploy && docker compose up -d --build`.
4. Создать администратора: `docker compose exec api python -m app.cli create-admin admin "Имя Фамилия"`.
5. Войти на `https://<домен>/admin`:
   - «Ученики» → загрузить `spisok_dlya_zhurnala.xlsx`, посмотреть изменения, нажать «Применить»;
   - «Пользователи» → завести охрану (логин и пароль), эдвайзеров (с их эдвайзери) и руководство («Получает отчёт»);
   - каждому эдвайзеру и руководителю нажать «Приглашение» и отправить ссылку — по ней Telegram привязывается к журналу.
6. «Проверка» — все пункты ✅.
7. На компьютере КПП открыть `https://<домен>/kpp` и войти учётной записью охраны.

Резервные копии БД каждые сутки складываются в `deploy/backups/` и хранятся 30 дней. Копируйте их с сервера в другое место.
Как восстановить — написано в `deploy/backup.sh`.

## Разработка

Всё запускается в Docker, локальный Python и Node не нужны.

```bash
# тесты backend
docker run --rm -v "D:\Git\kpp-journal:/repo" -w /repo/backend python:3.12-slim sh -c "pip install -q -e '.[dev]' && pytest -q -p no:cacheprovider"
```

```bash
# тесты и сборка frontend
docker run --rm -v "D:\Git\kpp-journal:/repo" -w /repo/frontend node:20-slim sh -c "npm ci && npx vitest run && npm run build"
```

```bash
# весь стек локально на http://localhost:8090 (в deploy/.env: COOKIE_SECURE=0, API_PORT=8090)
cd deploy && docker compose up -d --build db api && docker compose exec api python -m app.cli demo
```

Демо-пользователи: `admin`, `kpp`, `kotiki`, `primary`, `director`, пароль `demo-pass-123`. Данные вымышленные.

### Сервер в локальной сети, эдвайзеры из интернета

Если журнал стоит на сервере в локальной сети, а эдвайзеры должны заходить из Telegram из любой сети, используйте внешний сервер с белым IP и туннель WireGuard.
Пошаговая инструкция и объяснения: [deploy/edge/README.md](deploy/edge/README.md).

### Доступ из локальной сети

В `deploy/.env` задайте `API_BIND=0.0.0.0`, `API_PORT=8090`, `COOKIE_SECURE=0`, затем из `deploy/` выполните `docker compose up -d api`.
На другом устройстве той же сети откройте `http://<локальный-IP-компьютера>:8090`.
В брандмауэре разрешите входящий TCP-порт 8090 только из локальной подсети. Проброс порта на роутере не нужен.
Для отключения прямого сетевого доступа верните `API_BIND=127.0.0.1` и пересоздайте `api` той же командой.
HTTP и общие демо-пароли допустимы только для тестирования с вымышленными данными; для реальных данных используйте HTTPS и индивидуальные пароли.

## Структура

- `backend/app/services/` — нормализация ФИО, поиск, разбор времени, лист дня, отметки, разрешения, отчёт
- `backend/app/api/` — HTTP API; `main.py` — приложение и WebSocket
- `backend/app/bot.py` — Telegram-бот (привязка по приглашению, кнопка Mini App)
- `backend/app/importer.py` — загрузка и сверка списка; `cli.py` — служебные команды
- `frontend/src/pages/` — экраны КПП, эдвайзера, отчётов и админки
- `shared/search_cases.json` — общие примеры поиска: на них проверяются и Python, и TypeScript
- `deploy/` — docker-compose, Caddy (HTTPS), бэкапы
